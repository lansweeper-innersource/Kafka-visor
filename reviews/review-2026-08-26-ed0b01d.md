## P2 - Important

### [ARCH-1] `getApiCallers`/`buildApiProviderIndex` computed twice per `ServiceDetails` render — **FIXED**
**File:** `src/components/DetailPanel.tsx:282-285` (was), root cause `src/lib/graph-builder.ts:219-254`
**Confidence:** 90 (corroborated independently by architecture, performance [P3/95], simplicity [P3/90], typescript [P2/90])
**Issue:** `getBlastRadius` built its own `buildApiProviderIndex` and called `getApiCallers` internally, then discarded the inbound-only list. `ServiceDetails` then rebuilt the index and called `getApiCallers` again for the new "Called by" section — same O(services × consumesApis) scan run twice per render.
**Fix applied:** `getBlastRadius` now accepts an optional pre-built `index` and returns `apiCallers: string[]` as part of its result. `DetailPanel.tsx` builds the index once, passes it into `getBlastRadius`, and reads `blast.apiCallers` instead of calling `getApiCallers` a second time.

### [SILENT-4] `ArgoSection.handleCopy` unhandled clipboard promise rejection — **FIXED**
**File:** `src/components/DetailPanel.tsx:553-560`
**Confidence:** 80 (corroborated by typescript [P3/65])
**Issue:** `navigator.clipboard.writeText` was awaited with no try/catch inside an `onClick`-bound async function. A rejection (denied permission, non-HTTPS context) becomes an unhandled promise rejection with no user feedback.
**Fix applied:** wrapped in try/catch with `console.error` on failure.

### [TEST-GAP] Missing coverage for `getApiCallers` loop-exhaustion, dedup, aggregation, index-override, self-skip — **FIXED**
**File:** `src/lib/graph-builder.test.ts`
**Confidence:** 90/85/75/70/65 (test-quality + typescript corroborate)
**Issue:** The only "empty" test used a nonexistent service id, only exercising the early-return guard — never a real service with zero callers. No test proved the `break`-based dedup, multi-caller aggregation, explicit `index` override, or the self-skip guard.
**Fix applied:** added 5 new test cases (`getApiCallers`) plus 2 new assertions on `getBlastRadius` (`apiCallers` field, explicit index override). All 25 tests in the file pass; 57/57 project-wide.

### [ARCH-2 / PERF-2] No memoization of `getBlastRadius`/`buildApiProviderIndex` in `ServiceDetails` — **DEFERRED**
**File:** `src/components/DetailPanel.tsx:268-286`
**Confidence:** 75-90
**Issue:** `DetailPanel` isn't `React.memo`'d and `ServiceDetails` recomputes on every render, including ones triggered by unrelated `AppInner` state (team filters, context menu, edge editing). Verified with real data: ~146 services, ~87 total API-relationship strings — sub-millisecond today.
**Why deferred:** All 3 reviewers who raised it (architecture, performance, react) independently concluded this is not yet worth the `useMemo` wrapping given current catalog scale, and it's consistent with the rest of `DetailPanel.tsx` (no other section is memoized either — not new debt, pre-existing file-wide pattern). Revisit if `topology.json` grows ~5-10x.

### [TYPE-3] Unchecked `as` casts for `topologyId`/`ServiceNodeData`/`TopicNodeData` — **DEFERRED**
**File:** `src/components/DetailPanel.tsx:50,59,67,227,281,96`
**Confidence:** 85
**Issue:** `buildGraph`/`buildFlowNodes` return bare `Node[]`, so every consumer unchecked-casts `data`. The new `getApiCallers`/`getBlastRadius` call is directly downstream of the `topologyId` cast — a malformed flow definition would silently degrade to an empty "Called by" section rather than erroring.
**Why deferred:** Pre-existing pattern across the whole file, not introduced by this commit. Fixing it properly needs a discriminated `Node<T,K>` union threaded through `buildGraph`/`buildFlowNodes`/`DetailPanel` — a larger, cross-cutting refactor that deserves its own story rather than folding into this review pass.

### [TYPE-4] No `zod` validation at the `topology.json` import boundary — **DEFERRED (follow-up story)**
**File:** `src/App.tsx:19`
**Confidence:** 90
**Issue:** `const topology = topologyData as TopologyData` — no runtime validation anywhere despite the project standard mandating `zod` at boundaries. Root cause of why every downstream `as` cast "has to" exist.
**Why deferred:** Systemic, project-wide, out of scope for a 125-line diff touching 3 files. Needs a `zod` dependency addition — an architectural decision Boss should sign off on, not something to slip in during a review pass.
